# Kira Ultra Operating Brief

## Two P0 surfaces

### Agent `/`
Kira is the Kapruka Agent Challenge entry. Judges score this path. It must stay an immersive, full-screen conversation with real catalog search, delivery checks, checkout links, tracking, reorder, local language support, and Kira's opinionated Sri Lankan shopping voice.

### Shop `/shop`
The storefront is Kapruka.com reimagined. It must over-deliver at the same craft level as the agent: premium browse UX, product detail, shared cart, mobile polish, and a seamless path into Kira.

## Named rule

**Agent and Shop must feel like ONE product.**

That means one token system, one typography system, one dark liquid-glass material language, one cart, one voice, and one motion vocabulary across `/`, `/shop`, category pages, product pages, cart, checkout, and Kira dock.

## Loop rules

Every loop must review both surfaces:

1. Build fixes for the highest blockers.
2. Run lint/build and relevant automated tests.
3. Review agent and shop quality gates.
4. Update `SCORECARD.md`.
5. Commit and push.
6. Deploy or inspect deployment status.
7. Retest live when a deployment URL is available.
8. Loop again until all exit criteria pass.

## Next.js 16 notes

- `next dev` and `next build` use Turbopack by default.
- Dynamic route `params` and page `searchParams` are Promises and must be awaited in Server Components and route handlers.
- Metadata exports and `generateMetadata` are Server Component only.
- Route handlers use Web Request/Response APIs; dynamic route context `params` is a Promise.
- `next/image` external absolute URLs require `images.remotePatterns`; `fill` requires a positioned parent and useful `sizes`.
- Playwright should use `webServer` or a running built/dev server and semantic selectors.
