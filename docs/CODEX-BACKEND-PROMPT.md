## Context you must respect

- The app talks to the Kapruka MCP at `https://mcp.kapruka.com/mcp` via `lib/mcp-client.ts` (already exists, do not rewrite). MCP rate limits: **60 req/min/IP, 30-min server cache** — your sync must batch politely and never run tight loops.
- Product parsing already exists in `lib/mcp-parsing.ts` — reuse `extractProductsFromMcp` and `extractProductDetailsFromMcp`. Do not duplicate parsing logic.
- Shared types live in `types/index.ts` (`KiraProduct`, `KiraProductDetails`, etc.). Reuse them; extend only if needed via a new file `types/store.ts`.
- The storefront must keep working **even if the MCP is down or rate-limited** — that's the whole point of the database. Read path: DB → if empty/unconfigured, fall back to `data/seed-catalog.json` → only then (optionally) live MCP.

## Database: Neon Postgres

- Driver: `pg` (node-postgres). Add to `dependencies`. Use a singleton `Pool` so dev hot-reload doesn't exhaust connections.
- Connection via `process.env.DATABASE_URL` (Neon pooled connection string, `?sslmode=require`). Add it to `.env.example` (no real secret) and read from `.env.local` at runtime.
- All DB code must degrade gracefully: if `DATABASE_URL` is unset, `isDbConfigured()` returns false and callers use the JSON fallback. Never crash the build or a page render because the DB is missing.

### Schema — create `db/schema.sql`

```sql
create table if not exists categories (
  slug          text primary key,
  name          text not null,
  icon          text,                 -- lucide icon name, e.g. 'CakeSlice'
  blurb         text,
  rank          int  default 0,
  product_count int  default 0,
  updated_at    timestamptz default now()
);

create table if not exists products (
  id               text primary key,
  name             text not null,
  summary          text,
  description      text,
  price            numeric not null,
  currency         text default 'LKR',
  compare_at_price numeric,
  image            text,
  images           jsonb default '[]'::jsonb,
  category         text,               -- display name
  category_slug    text references categories(slug),
  url              text,
  in_stock         boolean default true,
  stock_level      text,
  variants         jsonb default '[]'::jsonb,
  addons           jsonb default '[]'::jsonb,
  attributes       jsonb default '{}'::jsonb,
  is_featured      boolean default false,
  rank             int default 0,
  raw              jsonb,              -- full original MCP object, for safety
  synced_at        timestamptz default now()
);

create index if not exists products_category_idx on products(category_slug);
create index if not exists products_featured_idx on products(is_featured);
create index if not exists products_name_trgm on products using gin (name gin_trgm_ops);
-- enable extension for the trigram index:
-- create extension if not exists pg_trgm;
```

## Sync script — `scripts/sync-catalog.mjs`
- Run with `node scripts/sync-catalog.mjs`. Add npm script `"sync": "node scripts/sync-catalog.mjs"`.
- Steps: `ensureSchema()` → for each category in a hardcoded `CATEGORIES` list (slug, name, icon, search query), call the MCP `kapruka_search_products` tool via `lib/mcp-client.ts` with that query (and a couple of sort variations to get breadth), parse with `extractProductsFromMcp`, then **upsert** into `products` (on conflict id do update), set `category_slug`, mark first N per category `is_featured = true`. - After DB upsert, also **write a snapshot** to `data/seed-catalog.json` (`{ categories: [...], products: [...] }`) so the JSON fallback always reflects the latest real catalog. If `DATABASE_URL` is unset, still produce the JSON snapshot (DB steps skipped).
