## Findings considered and rejected

Recorded so they are not re-audited next run:

- **"`next build` is broken by the lint errors."** REJECTED — verified
  `npm run build` exits 0; Next 16's build does not fail on these ESLint errors
  here. The errors are real (plan 003) but not a deployment blocker.
- **Secrets exposure.** REJECTED — `.env*` is git-ignored, no hardcoded
  keys/tokens, no `dangerouslySetInnerHTML`/`eval`/`innerHTML` anywhere in
  `app/`+`lib/`. Only `GROQ_API_KEY` / `DATABASE_URL` read from env. Nothing to do.
- **MCP singleton concurrency bug.** CONSIDERED, not planned — the
  `@modelcontextprotocol` SDK matches responses to requests by JSON-RPC id, so
  concurrent `callTool` on the shared client is by design; the
  invalidate-while-in-flight race is self-healing (a stale client's next call
  fails and re-invalidates). Not worth a plan; revisit only if real connection
  corruption is observed under load.
- **Checkout quantity has no upper bound / integer check** (`app/api/checkout/route.ts`
  validates `quantity < 1` but not a max or non-integer). CONSIDERED — low
  value (MCP and the cart UI bound it in practice); fold into validation if the
  checkout route is touched for another reason.
- **No security headers / CSP** (`next.config.ts`). CONSIDERED — low priority
  for a time-boxed challenge; the app has no XSS sink (no `dangerouslySetInnerHTML`).
  Defer.
- **Direction items** (wire the glass kit into real surfaces; same-day cut-off
  countdown; add-on upsell; guided gift-finder) are *not* defects and were
  presented separately to the maintainer; no plans written unless requested.
  Note: the "per-request date" backlog item is already implemented
  (`route.ts:611`).
