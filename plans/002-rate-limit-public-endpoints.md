## Why this matters

The app is judged as a **live public URL** with no authentication on its API
routes (by design — it's a public shopping assistant). `POST /api/chat` spends
the Groq free-tier budget on every call, and that budget is a hard **100,000
tokens per day, shared across all users** (the 70B model). There is **no
rate limiting anywhere** — confirmed: `express-rate-limit` is listed in
`package.json` but imported nowhere, and it cannot function in Next.js App
Router (it is Express middleware with no `req/res` Express objects in this
runtime). The concrete failure mode: a single abusive client, a scraper, or
even an organic traffic spike during judging exhausts the daily Groq budget,
after which the model cascade falls through to the last resort and every
subsequent user — including the judges — gets the "having trouble reaching
Kapruka" fallback. `POST /api/checkout` is likewise unthrottled and places real
orders via MCP. This plan adds a lightweight per-IP limiter in Next middleware
and deletes the dead dependency.

## Steps

### Step 1: Implement a pure token-bucket limiter in `lib/rate-limit.ts`

Create a small, dependency-free, in-memory limiter. Keep the logic pure and
injectable (pass `now` in) so it is unit-testable:
```ts
// lib/rate-limit.ts
type Bucket = { count: number; resetAt: number };
const buckets = new Map<string, Bucket>();

export type RateLimitResult = { allowed: boolean; retryAfterSec: number };

/** Fixed-window limiter. `key` is typically `${ip}:${route}`. */
export function rateLimit(
  key: string,
  limit: number,
  windowMs: number,
  now: number = Date.now()
): RateLimitResult {
  const b = buckets.get(key);
  if (!b || now >= b.resetAt) {
    buckets.set(key, { count: 1, resetAt: now + windowMs });
    return { allowed: true, retryAfterSec: 0 };
  }
  if (b.count < limit) {
    b.count++;
    return { allowed: true, retryAfterSec: 0 };
  }
  return { allowed: false, retryAfterSec: Math.ceil((b.resetAt - now) / 1000) };
}

// Opportunistic cleanup so the Map can't grow unbounded on a long-lived instance.
export function sweep(now: number = Date.now()): void {
  for (const [k, b] of buckets) if (now >= b.resetAt) buckets.delete(k);
}
```

**Verify**: `npx tsc --noEmit` → exit 0.

### Step 2: Add `middleware.ts` that applies the limiter to the two API routes

```ts
// middleware.ts
import { NextRequest, NextResponse } from "next/server";
import { rateLimit, sweep } from "@/lib/rate-limit";

// Tune to the Groq budget: chat is expensive, checkout places orders.
const LIMITS: Record<string, { limit: number; windowMs: number }> = {
  "/api/chat": { limit: 20, windowMs: 60_000 },      // 20 msgs / IP / min
  "/api/checkout": { limit: 8, windowMs: 60_000 },   // 8 orders / IP / min
};

export function middleware(req: NextRequest) {
  const path = req.nextUrl.pathname;
  const cfg = LIMITS[path];
  if (!cfg) return NextResponse.next();

  const ip =
    req.headers.get("x-forwarded-for")?.split(",")[0]?.trim() ||
    req.headers.get("x-real-ip") ||
    "unknown";

  sweep();
  const { allowed, retryAfterSec } = rateLimit(`${ip}:${path}`, cfg.limit, cfg.windowMs);
  if (allowed) return NextResponse.next();

  return NextResponse.json(
    { error: "Too many requests — please slow down a moment." },
    { status: 429, headers: { "Retry-After": String(retryAfterSec) } }
  );
}

export const config = {
  matcher: ["/api/chat", "/api/checkout"],
};
```
The `matcher` ensures middleware runs ONLY for these two routes (no overhead on
pages/assets). Pick the IP from `x-forwarded-for` (Vercel sets it).

**Verify**:
- `npx tsc --noEmit` → exit 0.
- `npm run build` → exit 0 and the build output lists a `ƒ Middleware` entry.

### Step 3: Manually confirm the limit fires

Start the dev server (`npm run dev`) and hammer the chat route past the limit:
```bash
for i in $(seq 1 25); do \
  curl -s -o /dev/null -w "%{http_code}\n" -X POST http://localhost:3000/api/chat \
  -H "Content-Type: application/json" -d '{"messages":[],"cart":[]}'; done
```
(On Windows PowerShell: `1..25 | % { (Invoke-WebRequest -Method POST -Uri http://localhost:3000/api/chat -ContentType 'application/json' -Body '{"messages":[],"cart":[]}' -SkipHttpErrorCheck).StatusCode }`)

**Verify**: the first ~20 responses are `200`, then responses become `429`.
(Exact 200 count may vary by ±1 due to the empty-body fast path returning
quickly — the transition from 200s to 429s is what matters.)

## Maintenance notes

- **This limiter is per-instance and best-effort.** Under heavy multi-instance
  scaling the effective global limit is `N_instances × limit`. For exact global
  limits, swap `lib/rate-limit.ts`'s `Map` for a shared store (Upstash
  Ratelimit / Vercel KV) behind the same `rateLimit()` signature — the
  middleware shouldn't need to change.
- Tune `LIMITS` against real traffic and the Groq budget; the values here are a
  conservative starting point.
- A reviewer should confirm the matcher doesn't accidentally cover page routes
  (which would add latency to every navigation).
